# askmd のコンセプト

## 一行要約

**「溜め込んだ `.md` を静かに速く読みながら、気になった箇所をその場で Claude に聞ける」** ための、Claude Code ユーザーのための軽量 GUI ビューア。

---

## なぜ作るのか

### 動機

出発点は、ごく個人的な苛立ちだった。**Claude Code や Claude Desktop は対話の中で頻繁に `.md` を吐き出す** — 設計メモ、調査サマリ、引き継ぎ資料、コードレビューの指摘まとめ。これを読むたびに VS Code を立ち上げて、サイドバーからファイルを探して、プレビューを開いて…という導線が毎回ひっかかる。「Finder で `.md` をダブルクリックしたら、静かに開いて、そのまま読めて、気になった箇所を Claude に聞ける」、それだけの道具が欲しかった。

この体験を一般化すると、ドキュメントを `.md` で書いて `docs/` に溜めていく開発スタイルが定着している。Claude Code を使っているとこれは特に顕著で、設計メモ・議論ログ・API ノート・引き継ぎ資料がどんどん増える。

そうして溜まった docs を **読むとき** に、ちょうどいい道具がない。

- **VS Code の Markdown Preview**: コードと混ざって読むにはいいが、「読書モード」としては視界が賑やかすぎる。`.md` だけに絞って眺める用途ではない
- **Obsidian**: 強力だが重い。Vault 概念、プラグイン、グラフビュー、独自ファイル (`.obsidian/`)。「ちょっと読みたい」用途にはオーバーキル
- **Typora**: きれいだが有料、かつエディタ寄り
- **MarkView**: 単一ファイルビューアに特化。ディレクトリツリーを持たない
- **markdown-explorer (jersou)**: コンセプト完全一致だが 2018 年で開発停止、Electron 製で古い
- **Ferrite**: Rust + egui 製軽量。ただし Markdown/JSON/YAML/TOML 対応のエディタで、macOS サポートは experimental。`.md` 専用ではない
- **MDChat**: CLI で md ノートに LLM 質問できる。GUI ではない

「**`.md` だけを読むことに絞った軽量 GUI**」と「**選択した箇所を Claude に質問できる**」の組み合わせは、明確に空席になっている。

### 誰のためか

主に **Claude Code を日常的に使っていて、docs/ に md を溜め込んでいる人**。手元に `claude` CLI が既にインストールされている前提で作る。これにより、Anthropic API キーを別途管理する面倒も、課金の二重化もなく、ユーザーの既存 Max/Pro サブスクリプションをそのまま流用できる。

### 誰のためではないか

- Markdown で **書く** 人 (エディタが欲しい人は VS Code / Obsidian / Typora を使うべき)
- ノート管理 / タグ / バックリンク / グラフビューが欲しい人 (Obsidian の領域)
- コードを読みながらついでに md を見たい人 (VS Code で十分)
- Claude Code を使っていない人 (本ツールの質問機能が意味をなさない)

ターゲットを絞り込むことで、設計のブレをなくす。

## 設計思想

### 1. サクサク最優先

このツールが成立するかどうかの生命線。起動、ファイル切り替え、検索、回遊のすべてが **即時** に感じられること。

- Tauri (Rust + WebView) で起動速度とメモリフットプリントを抑える
- 一度開いたファイルのレンダリング結果はメモリキャッシュ
- ツリー走査はキーボードで完結
- 大量の md (数十〜数百) がツリーに並んでも動きが重くならないこと

「Obsidian を開くのが億劫な気分のとき、askmd を開きたい」と思われる軽さが目標。

### 2. キーボードファースト

マウスを使わずに完結する UX。

- `↑` / `↓` / `j` / `k`: ツリー内の移動
- `Enter`: ファイルを開く
- `/`: インクリメンタル絞り込み (fzf 的)
- `Cmd+P`: ファイル名クイックスイッチ (VS Code 的)
- `Cmd+[` / `Cmd+]`: 履歴の戻る/進む
- `Cmd+L`: 選択範囲を Claude に質問

「マウスに手を伸ばすたび集中が切れる」という体感を排除する。

### 3. `.md` に絞る

`.md` だけを扱う。JSON/YAML/TOML/コードファイルは**ツリーに表示しない**。`.git` / `node_modules` / `.obsidian` などの隠しディレクトリもスキップ。これは「ノイズを減らす」という設計上の強い意志の表明で、多機能化を防ぐ防波堤として機能する。

`.md` を含まないディレクトリはツリーから畳まれて消える。docs が散らばっていても、`.md` だけで構成された仮想的なツリーが浮かび上がる。

### 4. Claude 連携は CLI 流用

質問機能の実装方式として、3つの選択肢があった：

| 方式 | 利点 | 欠点 |
|---|---|---|
| (a) Anthropic API キー直接 | 標準、柔軟 | ユーザーに課金ハードル、キー管理負担 |
| (b) `claude` CLI 子プロセス | 認証不要、既存サブスク流用 | Claude Code インストール前提 |
| (c) Claude Desktop deep link | 対話継続しやすい | **現状プリフィル URL が存在しない** (2025/10 に削除) |

**(b) を採用**。ターゲットが既に Claude Code ユーザーに絞られているため、Claude Code の認証・請求・設定をそのまま活用できる。API キーや課金の面倒を一切ユーザーに押し付けない。

`.md` を開いている場面で、テキスト選択 → `Cmd+L` → `claude -p "..."` が子プロセスで走り、回答が右ペイン下部に stream で表示される。Cursor の Composer や ChatGPT の "Ask about this selection" に近い体験を、**ローカルで、既存の契約内で** 実現する。

### 5. ビューアであり、エディタではない

編集機能を持たない。これは制約であり、同時に設計上の強い方針でもある。

- 編集したくなったら、自分の好きなエディタ (VS Code / Neovim / Zed) で編集してください、というスタンス
- ファイル変更監視 (`notify` crate) で、別エディタで保存すれば askmd 側は即座に反映される
- askmd は「読む・検索する・問う」ための場所

これにより UI が爆発的にシンプルになり、「さくっと開いて読む」体験を壊すノイズ (ツールバー、保存ボタン、フォーマット設定、プラグイン) を最初から持たない。

---

## 非目的 / やらないこと

明示的に **やらない** ことを並べる。これは「何を作らないか」を決めることで「何を作るか」を守るための項目。

- Markdown 編集機能 (`.md` を書きたい人は別エディタで)
- `.md` 以外のファイルの表示 (コード、JSON、YAML は対象外)
- ノート管理 (タグ、バックリンク、グラフビュー、Vault 的な概念)
- リアルタイム協調編集
- クラウド同期 (ファイルシステムに置かれているものを読むだけ)
- Anthropic API キー管理 (CLI 流用)
- プラグインシステム (コードは小さく保つ)
- マルチウィンドウ / タブ (1ウィンドウ1ルート、回遊はツリー内で)

これらは誘惑として出てくるが、やらない。

## 差別化ポイント (まとめ)

| 既存ツール | askmd との違い |
|---|---|
| VS Code Markdown Preview | コードと混ざらず、`.md` だけの静かな読書空間 |
| Obsidian | Vault 不要、プラグインなし、起動10倍速い、編集しない |
| Typora | 無料、編集しない、ディレクトリ回遊が主役 |
| MarkView | ディレクトリツリーがある |
| markdown-explorer | 2026 年の技術スタック (Tauri, Rust, 型安全)、現役メンテ |
| Ferrite | `.md` 専用、macOS ファースト、ビューア特化、Claude 連携 |
| MDChat | GUI、ディレクトリ回遊、選択範囲質問 |

**唯一無二の組み合わせ**: `.md` 専用 + ディレクトリツリー + 軽量 GUI + Claude CLI 流用の選択範囲質問。

## 技術的な意思決定の記録

### Tauri を選んだ理由
- Electron は起動が遅くメモリが重い。「サクサク」要件と相反する
- egui/tauri/wry の中で、Markdown のリッチレンダリングに最も素直なのが Tauri (WebView)
- csm (claude-session-manager) で既に Tauri ノウハウがあり、コード規約も流用できる

### バンドラを使わない理由
- `tsc` 単体でコンパイルする csm の構成を継承
- ES Modules のネイティブサポートで十分、Webpack/Vite は過剰
- ビルド時間短縮、依存の最小化

### markdown-it を選んだ理由
- GitHub Flavored Markdown に近い挙動、プラグイン豊富
- csm で実績があり、レンダリング品質が確認済み
- DOMPurify と組み合わせて XSS を防ぐ

### 名前「askmd」の由来
候補と検討：
- `mdview` → npm/Cargo/GitHub に既存多数、検索性 NG
- `mdchat` → MDChat (先行者) と被る
- `mdnav`, `readmd`, `mdglance` → 空きだが機能が伝わりにくい
- **`askmd`** → 「md に問う」「md を尋ねる」の2つの意味、短い、空き、検索性◎

質問機能を前面に押し出す命名。「読むだけ」にも使えるが、「読みながら聞ける」のが特徴、という思想をそのまま名前にした。

## 将来の方向性 (現時点の想定)

Phase 2 以降で検討：

- **全文検索**: docs 全体への検索。tantivy (Rust) を使う。csm で実装済みなのでノウハウ流用可能
- **ターミナル連携モード**: Cmd+Shift+L で `osascript` 経由で iTerm/Terminal を開き `claude` を対話モードで起動。長い対話が必要な時用
- **Claude Desktop 連携**: Anthropic が URL プリフィルを再実装したら対応
- **最近開いたディレクトリの UI**: 起動画面に最近開いた 3〜5 件
- **リリース配布**: GitHub Releases + 自動アップデータ (csm の仕組み流用)
- **CLI サブコマンド**: `askmd index` で明示的にインデックス再構築、など

やらないかもしれないもの：

- プラグインシステム — コードを小さく保つ方針と相反
- 複数ルートの同時オープン — 1ルート1ウィンドウ原則を崩したくない
- クラウド同期 — 責務外

---

## まとめ

askmd は、**既にある自分の docs を、既にある Claude Code の認証を使って、軽快に回遊しながら問える**、ただそれだけの道具。

多機能化の誘惑は多いが、「`.md` を読む / 問う」という一点に絞り続けることで、他のどのツールにもない居場所を作る。
